# ユビキタス言語（用語集）

会話・ドキュメント・コードで同じ言葉を使うための辞書。「コード名」は `src/domain/` での実際の名前（型・メソッド・項目）。

状態: **確定** = ドメインエキスパートと合意済み / **仮** = 提案中で要確認

## 共通

| 用語 | コード名 | 意味 | 状態 |
|---|---|---|---|
| 家族 | Household（`members` の 2 人） | アプリを使う夫婦 2 人。役割は固定せず、どちらも同じことができる | 確定 |
| いつもの人数 | `HOUSEHOLD_SERVINGS`（= 2） | 家族がいつも作る人数。作る人数の初期値で、基準人数の記載がないレシピもこの人数分とみなす | 確定 |
| 家族メンバー | Member（`members`） | 家族の一人。献立を決める人・買い物に行く人は日によって変わる。登録された 2 人だけがデータを読み書きできる | 確定 |

## レシピ帳

| 用語 | コード名 | 意味 | 状態 |
|---|---|---|---|
| レシピ | `Recipe` | 料理の作り方。材料・作り方・出典を持つ | 確定 |
| 材料 | `Ingredient` | レシピに書かれた「食材＋分量＋下ごしらえ」。DB では `{ name（食材）, amount, preparation }` | 確定 |
| 食材 | `Food` | 店で買う物としての名前。部位や種類まで含む（豚ばら肉と豚ロース肉は別の食材。部位の書かれていない豚肉も別） | 確定 |
| 下ごしらえ | `preparation` | みじん切り・薄切りなど、買った後の扱い。買う物には影響しない | 確定 |
| 分量 | `Quantity` | 「大さじ2」「200g」「少々」など。数えられるもの（`countable`）と、数えられないもの（`uncountable`: 少々・適量）がある | 確定 |
| 基準人数 | `Servings` | レシピの分量が何人分か。取り込み時に「〇人分」「〇人前」の記載を探す。見つからなければ 2 人分とみなし（`assumed`）、そのことを画面に示す | 確定 |
| 出典 | `Source`（DB では `source_type` / `source_url`） | レシピの元になった YouTube 動画や Web ページ、写真（料理本・雑誌のページ、スクリーンショット）。手入力と写真なら URL はない | 確定 |
| 元の画像 | `sourceImages`（DB では `source_images`） | 写真から取り込んだときに選んだ画像。複数枚あれば選んだ順に 1 つのレシピとして読み、後から見返せるよう残す | 確定 |
| レシピを削除する | `deleteRecipe` | 「もう作りたくない」レシピを手軽に消す。作った記録や評価は残さない | 確定 |

## 献立

| 用語 | コード名 | 意味 | 状態 |
|---|---|---|---|
| 食事 | `Meal` | ある日の朝・昼・夜の 1 回分の食事。外食のこともある | 確定 |
| 食事区分 | `MealTime` | 朝 / 昼 / 夜（`breakfast` / `lunch` / `dinner`） | 確定 |
| 献立 | （`menu` コンテキスト） | 1 回の食事で食べる品の組み合わせ。夜は品が 3 つほど、昼は一品物が多い。コードでは食事（`Meal`）に並ぶ品と残り物として表す | 確定 |
| 品 | `Dish` | 献立に並ぶ 1 つの料理。必ずレシピを参照する。バナナのようなレシピのない物は献立に入れない | 確定 |
| 作る人数 | `servingsToCook` | 品をその回に何人分作るか。初期値は 2 人。カレーなど翌日も食べるときは増やす | 確定 |
| 外食 | `eatingOut` | 家で作らない食事。献立画面で外食と分かるようにする | 確定 |
| 多めに作る | （作る人数 > いつもの人数） | 翌日も食べるために作る人数を増やすこと（例: カレー） | 確定 |
| 残り物 | `Leftover` | 多めに作った品を後日食べること。献立に「カレー（残り物）」のように表示する。新たに買い物は発生しない | 確定 |
| 残り物の候補 | （`fetchLeftoverCandidates`、`LEFTOVER_KEEP_DAYS` = 7） | 残り物として選べる品。その食事より前の 1 週間に、多めに作った品（作り置きなどで 1 週間は食べることがある） | 確定 |

## 買い出し

| 用語 | コード名 | 意味 | 状態 |
|---|---|---|---|
| 買い物メモ | `ShoppingMemo`（DB では `shopping_memo`） | 家族で 1 枚だけの、自由に書けるメモ帳。ずっと使い続け、チェックした状態も共有する。食材も日用品も文房具も同じメモに書く。画面では「買い物リスト」と呼ぶ | 確定 |
| チェックできる行 | `☐` / `☑`（`parseMemoLine`） | ☐ で始まる行。買う物を書く行で、☑ にするとチェック済み。それ以外の行は見出しや一言メモ、空行は買い物先などの区切りとして扱う | 確定 |
| 書く | `write`（画面の使い方） | メモ帳と同じように、好きな場所に自由に書いたり直したりすること。☐ の行で改行すると次の行にも ☐ が付く | 確定 |
| 買い物中 | `shop`（画面の使い方） | 店で使うときの使い方。行をタップして ☐ ↔ ☑ を切り替える（キーボードは出ない） | 確定 |
| 献立の材料を反映 | `reflect` / `reflectMenuIngredients` | 期間（今日・明日・3 日分・1 週間）を選び、まだ反映していない献立の品の材料を、作る人数に合わせて合算し、見出しを付けてメモの末尾に足すこと。反映した後で献立を変えても、メモは変わらない | 確定 |
| 反映済みの品 | `reflectedDishIds` | すでに材料をメモに入れた品。2 回目の反映では入れない | 確定 |
| 足し引き | （メモの書き換え） | 冷蔵庫の中身に合わせて、メモを書き足したり、直したり、消したりすること。材料の入れ替え（豚ばら肉→豚こま）もこれで行い、献立やレシピは変えない | 確定 |
| 買い出し | （モデルには持たない） | 週 3 回ほど。主に妻、会社帰りや土日は夫も行く | 確定 |
| 買った | `☑` / `removeDoneLines` | チェックできる行を ☑ にすること。☑ の行は「☑ を消す」を押したときだけまとめて消える。買えなかった物は ☐ のまま残る | 確定 |
| 常備品 | （モデルには持たない） | 塩・醤油など家に常にあるもの。特別扱いはしない（反映で入ったら、不要なら足し引きで消す） | 確定 |

## 使わない言葉

| 言葉 | 理由 |
|---|---|
| メニュー | 「献立」と混ざるため使わない |
| 主菜・副菜・汁物 | 献立の中で区別しないことにしたため、モデルには持たない |
| 食材（買い出しの中で） | 買い物メモには日用品も入り、アプリは行の中身を読み分けない。「食材」はレシピ帳の言葉 |
| お店（スーパー・ドラッグストアなど） | モデルには持たない。分けたいときはメモに見出しや空行を自由に書く |
| 買う物・品名・区切り・並び順・出どころ・使う日 | 買い物リストを 1 行ずつの項目として持っていたときの言葉（`ShoppingItem` など）。メモ帳にしたので使わない（古い `shopping_items` テーブルは 0009 で削除済み） |
| meal_plans | 第 3 段階で `meals`・`dishes`・`leftovers` に置き換えて廃止した（0004 で削除済み） |
| Recipe / Ingredient（DB の行の意味で） | コードでは DB の行の形を `RecipeRow`・`IngredientRow` と呼び、ドメインの `Recipe`・`Ingredient` と区別する |
